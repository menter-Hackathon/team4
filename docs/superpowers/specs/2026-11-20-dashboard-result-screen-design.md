# ダッシュボードを「ふたまる診断の結果画面」にする（設計メモ）

- 作成: 2026-11-20
- 対象: `scripts/dashboard.html`・`scripts/dashboard.py`・`agent/plant/plant_type.py`・`agent/plant/store.py`（仕様 §6.6、#59・#64）
- 大きさ: 中くらい（エージェントの会話・振り返りには触らない）

## なぜ

ふたまるで作りたかったのは、育てた人の「らしさ」（どう話しかけたか、どう優しくしたか、いつ会いに来たか）に
合わせて性格が育つ植物（ショーンさんの FB、2026-11-20）。
今できているのは「どんな人か」を聞き取る側（会話・振り返り）までで、**その結果どんな性格に育ったか**が画面で見えない。
今のダッシュボードは数字とグラフの管理画面で、「ただ喋る bot」に見えてしまう。

そこで、性格診断の結果ページのように「あなたのふたまるは、こんな子に育ちました」を一発で見せ、
その下に「どう育てたからこうなったか」を並べる。発表では画面共有で審査員に見せる（`docs/demo-day.md`）。

- 方向性の案（絵本・育成ゲーム・日記）: https://claude.ai/artifact/LgsJL5XV2eSjicjUNvsnBe — 日記は「性格が一発で分からない」ので不採用
- 結果画面のモック: https://claude.ai/artifact/GE8BJCY9nxzfH3miGU3uUQ — これを形にする

## ゴール

- 育てた人ごとに、タイプ名・イラスト・キャッチコピーを一番大きく出す（ちゃむさんのイラストの世界観にそろえる）
- 4 軸を「おしゃべり ⟷ ひかえめ」のように両はじに名前をつけたゲージで見せ、どちらに育ったかを数字なしで分かるようにする
- タイプごとの少し長い説明文（2〜3 文）を出す
- 「こんなふうに育てられた」として、DB にある事実を出す: 話した回数、水をもらった回数、よく話しかけてくれた時間帯、
  会いに来てくれた間隔、1 回の会話の長さ、いちばん大きく動いた軸
- 発表の Windows の PC（ショーンさんの PC）でも同じ見た目で出る

## やらないこと

- エージェントの会話・振り返り・性格の決め方（`personality.py`・`reflection.py`・`prompt.py`）は変えない
- 生活リズム（夜ふかしなど）を性格に反映するしくみ。やるなら別の PR（下の「残っていること」）
- 日記・吹き出しは入れない

## こうなったら失敗

- **画面が嘘をつく**: 今の性格の決め方が見ていないことを、性格の原因のように書く。
  例: 「夜おそくに話しかけた → クールに育った」。今の振り返りは時刻を見ていない。
  時間帯・間隔は「事実」として並べるだけにし、「→ だからこう育った」の矢印は付けない
- 発表の PC で文字化け・崩れ・イラストが出ない
- 3 秒ごとの更新でちらつく・タブが勝手に切り替わる（今の動きが壊れる）
- 記憶や要約を HTML として入れる（今は textContent。これは守る）

## 制約

- 新しいライブラリを足さない。Chart.js 4.4.1（CDN）は成長曲線にだけ使い続ける
- 127.0.0.1 だけで待ち受ける・DB は読むだけ、は変えない（記憶が見えるため）
- タイプの名前と説明はオリジナル（恋愛 MBTI・ラブタイプ 16 診断などの名前や文は使わない、`plant_type.py` の方針）
- テストを先に書く（`tests/scripts/test_dashboard.py`・`tests/plant/` の該当ファイル）

## 決めたこと

### 画面（`dashboard.html`）

カード 1 枚 = 株 1 つ。タブ（お客さん・人ごと）はそのまま。最初に開くタブも今と同じ（登録が 1 人ならその人）。
カードの中は上から:

1. **結果**: 「〇〇さんのふたまる」「N 日育てた結果…」、イラスト（大きく）、タイプ名、キャッチコピー（今の `description`）
2. **せいかく**: 4 軸のゲージ。真ん中（0.5）から伸びる棒で、伸びた側の名前を色付きにする
   - おしゃべり ⟷ ひかえめ（talkativeness）／あまえんぼ ⟷ クール（affection）／げんき ⟷ まったり（energy）／しりたがり ⟷ ききじょうず（curiosity）
3. **説明文**: タイプの長い説明（新しく足す `detail`）
4. **こんなふうに育てられた**: 数字 3 つ（話した回数・水をもらった回数・よく話しかけてくれた時間帯）と、事実の箇条書き
   （会いに来てくれた間隔、1 回の会話の長さ、いちばん大きく動いた軸）
5. **くわしく**: 成長曲線（今の折れ線）、覚えていること、前回の会話、方言 — 今の情報は消さずに下へ移す

レーダーチャートは 2 のゲージに置き換える。見た目はモックの色・丸ゴシック（Google Fonts ＋ Mac/Windows の字体を後ろに並べる）。

### データ（`dashboard.py`・`store.py`）

`/api/state` の各ビューに `growth` を足す（既存のキーは変えない）:

```json
"growth": {
  "talks": 30,               // その人との会話の回数（終わった会話）
  "waterings": 11,           // その人が水をあげた回数
  "time_band": "夜",         // 会話を始めた時刻で一番多い時間帯（朝・昼・夕方・夜・深夜）。会話 0 回なら null
  "interval_days": 1.0,      // 会話と会話の間の平均日数。2 回未満なら null
  "avg_turns": 8.1,          // 1 回の会話でのユーザー発話の平均
  "biggest_change": {"trait": "affection", "delta": 0.5}  // 最初と今の差がいちばん大きい軸。履歴が 1 行なら null
}
```

- 時間帯の区切りは作る人に任せる（例: 朝 5〜10 時、昼 10〜16 時、夕方 16〜19 時、夜 19〜22 時、深夜 22〜5 時）
- お客さんのビューは person_id が NULL の会話・水やりで数える
- 集計に要る読み取り（その人の会話の開始時刻と発話数・水やりの回数）は `PlantStore` に読むだけのメソッドを足す

### タイプの説明文（`plant_type.py`）

`PlantType` に `detail`（2〜3 文）を足し、17 タイプぶん書く。下書きは AI が書き、ちゃむさん・ショーンさんに PR で見てもらう。
`/api/state` の `type` に `detail` を足す。

## 作る人に任せること

- 色の値・文字の大きさ・余白・角の丸さ、狭い画面（720px 以下）での並べ方
- Google Fonts のどの丸ゴシックにするか
- 時間帯の区切り、数字の丸め方、箇条書きの言い回し（ただし原因のように書かない）
- `growth` を作る関数の分け方
