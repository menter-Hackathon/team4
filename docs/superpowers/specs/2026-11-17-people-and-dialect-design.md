# 話し相手の見分けと方言 設計

2026-11-17 ／ ケーノ・Claude Code

## 目的と理由

ふたまるが**話し相手を見分け、その人の方言をまねて話す**ようにして、植物の「らしさ」を表現する。

- 一つの株に家族など複数の人が話しかける。植物は今話しているのが誰かを知り、その人の記憶と方言で接する
- 方言は、話しているうちに相手からうつる（「育て方で性格が変わる」と同じ考え方）
- 発表（11/22）では、たろうには関西弁、はなこには博多弁で話す、のように見せる

## やること・やらないこと

**やること**
- 名乗りから話し相手を見分ける（声では見分けない）
- 方言 4 つ（標準語・関西弁・博多弁・広島弁）を、会話から自動で判定して人ごとにうつす。手で固定もできる
- 性格・記憶・前回の会話・方言を人ごとに分ける。同じ株でも、相手によって違う性格で接する

**やらないこと**
- 声（声紋）による見分け。発表のあとに検討する
- 同時に複数人が話すこと。**一人ずつ話す前提**
- 1 回のセッション（起きてから眠るまで）の途中で話し相手が替わること。替わるときは、一度眠らせてから次の人が起こす
- 4 つ以外の方言、STT（聞き取り）の方言対応、方言の混ざり具合の段階

**失敗とみなすこと**
- デモの本番で狙った方言にならない（→ 手で固定できるようにして防ぐ）
- 1 回の判定ミスで方言がころころ変わる
- 名前の確認のせいで、返事が目に見えて遅くなる・会話がぎこちなくなる（毎回しつこく名前を聞くなど）
- 今ある株の記憶・会話ログが消える

- LLM は Gemma 4 E4B（本番）か OpenAI（開発中の代用）。どちらでも動くよう、構造化出力（JSON スキーマ）で名前・方言を取り出す

## 作り方の候補

**見分け方**（選んだのは A）
- **A. 名乗ってもらう（採用）**: 起きたときの発話から名前を拾い、わからなければ植物から聞く。今の仕組みの延長で作れる
- B. 声で聞き分ける: 声紋のモデルと登録の手順が新しく要り、ESP32 のマイクで精度が出るか未知数。5 日では危ない
- C. 見分けない（今のまま）: 「その人の方言」が表現できない

**方言の決め方**（選んだのは C）
- A. 会話から自動で判定するだけ: 判定が外れるとデモで狙った方言にならない
- B. 手で設定するだけ: 「その人の方言がうつる」感じが出ない
- **C. 自動で判定し、手で固定もできる（採用）**

## 決めたこと

### 人（話し相手）
- 株ごとに知っている人の一覧を持つ（新しいテーブル `people`: id, plant_id, name, dialect_override, created_at）
- 同じ人かどうかは LLM に判断させる。STT は「たろう」「太郎」「タロウ」と書き方が揺れるので、文字の一致では比べない

### 会話の流れ（1 セッション）
1. 「ふたまる」で起きる。この時点では相手は未確定
2. **相手が未確定の間**、ユーザーの発話ごとに LLM で名前を探す（「ふたまる、たろうだよ」の「たろうだよ」も対象）。知っている人の一覧を渡し、「一覧のこの人」「新しい人（名前）」「名乗っていない」のどれかを JSON で返させる
   - この名前探しは返事の前に 1 回行う（返事が少し遅れるのは、相手が確定するまでの最初の数回だけ）。時間がかかりすぎたら（数秒）名乗っていない扱いにして返事を優先する
3. 相手が決まったら、その人の記憶・前回の会話・方言でシステムプロンプトを作り直し、TTS の指示も方言に合わせて替える。新しい人なら `people` に登録する
4. 相手が未確定の間は、植物の返事の指示に「まだ相手の名前がわからないので、自然に名前を聞く」を足す。ウェイクワードだけで起こされたときの挨拶でも名前を聞く。**聞くのはセッションの最初の 3 回の発話まで**。それでも名乗らなければ「お客さん」として扱い、それ以上は聞かない
   - **お客さんに決まったら、そのセッションでは名前探しもやめる**（返事の遅れを増やさないため。途中で名乗っても、そのセッションはお客さんのまま）【作る人の判断】
5. お客さん（未確定のまま）のセッションでは、標準語で話し、全員に共通の記憶だけを使う

### 人ごとに分けるもの・株で 1 つのもの
- **人ごと**: 性格（4 軸）、記憶、前回の会話、方言（2026-11-17 ケーノ決定: 性格も人ごと）
- **性格を人ごとに分ける**
  - 人ごとに 4 軸の値を持つ（`people` に `talkativeness`・`affection`・`energy`・`curiosity` を足す）。その人との振り返りで、その人の性格だけが動く
  - 新しく登録した人の性格は、初期値（全部 0.5）から始める。人ごとの関係がゼロから育つことを見せるため【作る人の判断】
  - おしゃべり度の「行動から見た目標値」（直近 7 日の話しかけ回数 ÷ 100）も、その人の話しかけ回数で数える
  - 話題を振るまでの秒数（おしゃべり度から決まる）も、相手が決まったらその人の性格で決め直す
  - 性格の移り変わりの記録（`trait_history`）に `person_id` を足し、人ごとに成長を追えるようにする
  - お客さん（相手が決まらない）のセッションと、この機能より前からの性格は、株の性格（今の `plants` の 4 軸）を使い、お客さんとの振り返りで動く。成長の早送りデモ（`scripts/simulate.py`）は人を使わないので、今までどおり株の性格で動く
- 記憶は「その人の記憶」と「全員に共通の記憶」（今ある記憶はすべてこちら）に分ける（`memories.person_id`、NULL なら共通）。プロンプトには、その人の記憶と共通の記憶を合わせた中から上位を入れる
- **ある人の記憶は、ほかの人との会話では使わない**（2026-11-17 ケーノ決定。一人ひとりと別々の関係を育て、人に話されたくないことを別の人にばらさないため）
  - 振り返りで LLM に見せる既存の記憶も、そのセッションの相手の記憶と共通の記憶だけにする
  - 振り返りで書き換えられるのは、見せた記憶だけ。ほかの人の記憶の id が返ってきても無視する
  - 共通の記憶を書き換えても、共通の記憶のまま（その人の記憶には移さない）
  - お客さんのセッションでは共通の記憶だけを見せ、新しい記憶は共通の記憶として保存する
- 前回の会話は、その人との直近のセッションの要約を使う。お客さんのセッションでは、お客さんのセッション（`person_id` が NULL）の直近の要約だけを使い、名前のわかった人の会話は見せない。この機能より前の会話（すべて `person_id` が NULL）は、お客さん側の要約として扱う【作る人の判断】
- セッションに相手を記録する（`sessions.person_id`、NULL ならお客さん）

### 方言
- 振り返り（reflection）で、LLM がそのセッションの相手の方言を判定する。値は `standard` / `kansai` / `hakata` / `hiroshima`、判断できないとき（発話が短い・少ない）は `unknown`。セッションごとに保存する（`sessions.owner_dialect`）
- 人の方言は、**その人との直近 5 回の判定（`unknown` を除く）の多数決**。同数なら新しいほうを優先する。判定が無ければ標準語
- 手で固定した人（`people.dialect_override`）は、判定に関係なく固定した方言で話す
- 話し方への反映
  - システムプロンプトに方言の指示を 1 段落足す（例:「関西弁で話す（例: 〜やで、〜やん、ほんまに）」）。標準語なら足さない
  - TTS の指示（`TTS_INSTRUCTIONS`）の後ろに方言のイントネーションの指示を足す。OpenAI の音声で違和感があれば、TTS 側は外す
- 振り返りの新しい記憶は、そのセッションの相手の記憶として保存する（お客さんなら共通の記憶）

### 手で操作するコマンド（`scripts/people.py`）
- `--plant-id a1`: 知っている人の一覧と、それぞれの性格（4 軸）・方言（自動か固定か、直近の判定）を表示
- `--plant-id a1 --person たろう --dialect kansai`: 方言を固定（その人がまだいなければ登録する）
- `--person` は、カタカナ→ひらがななどをそろえた上で一致する人を探す（`wake.normalize` と同じそろえ方）。漢字と仮名の違い（「太郎」と「たろう」）は区別されるので、一覧に出た名前をそのまま使う。人の id でも指定できる（`--person-id 3`）【作る人の判断】
- デモでは、事前にこのコマンドで人を登録・方言を固定しておき、本番では「たろうだよ」を LLM が登録済みの人に結び付ける。名前探しの指示には、知っている人の一覧を必ず渡す【作る人の判断】
- `--plant-id a1 --person たろう --auto`: 固定を解除
- Docker では `docker compose exec agent python -m scripts.people ...`

### DB の引き継ぎ
- 起動時に、無いテーブル（`people`）と無い列（`memories.person_id`・`sessions.person_id`・`sessions.owner_dialect`・`trait_history.person_id`）を足す。今あるデータは消さない。今ある記憶はすべて共通の記憶に、今ある性格は株の性格（お客さん用）になる

### デモのために
- 人を替えるには一度眠らせる必要がある。発表では `SLEEP_AFTER_SECONDS`（今は 60 秒）を短くして見せる（`.env` で設定済みの項目）

## 作る人に任せること
- 方言ごとの指示文と語尾の例、名前を聞く指示・お客さんの扱いの文面
- 名前探しの LLM 呼び出しの指示文と時間切れの秒数
- 振り返りの指示文で方言の判定をどう説明するか
- 成長の早送りデモ（`scripts/simulate.py`）を、人・方言に対応させるかどうか
